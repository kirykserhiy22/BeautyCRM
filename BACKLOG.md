# BeautyCRM — беклог ідей і доробок

Список того, що Сергій хоче змінити або додати. Це не план на найближчий тиждень, а «склад» ідей:
звідси задачі переносяться в Kanban (одна задача = одна гілка `feature/<назва>`).

Нові ідеї спершу падають у розділ «Вхідні», а потім розкладаються по розділах.
Технічні проблеми в коді — у `CLAUDE.md` → «Відомі проблеми».

---

## 1. Продукт: майстер і салон

- [ ] **Вибір типу акаунта при реєстрації:** майстер-одинак або салон.
  Модель даних під це вже закладено (workspace + ролі `owner` / `admin` / `master`).
- [ ] **Вибір професії для майстра.** Для MVP лише ті професії, яким підходить поточний функціонал
  (записи, нотатки, свої послуги й ціни):
  - перукар-колорист
  - манікюр / педикюр
  - лешмейкер
  - брови / вії
- [ ] **Функції для салону:** запрошення майстрів, ролі, спільний календар. Детальніше розписати пізніше.

## 2. Монетизація і підписки

- [ ] **Безкоштовний пробний період** 1–2 місяці, потім обов'язковий вибір тарифу.
- [ ] **Тарифи з лімітами**, наприклад «Базовий» — до 100 клієнтів, «Про» — 500+ клієнтів, плюс додаткові функції.
- [ ] **Мінімальний безкоштовний рівень** після пробного періоду: обмеження за кількістю клієнтів і/або функціями.
  Основний дохід — з підписок.
- [ ] **Settings → «Мій план»:** поточний тариф, скільки днів пробного періоду лишилось, перехід на інший тариф.
- Технічно: покупки через App Store (StoreKit), перевірка підписки й на сервері, щоб ліміти не можна
  було обійти. Тарифи і ліміти продумати до запуску в App Store.

## 3. Бренд

- [ ] **Ідея і сенс додатку:** чим він відрізняється від тисяч інших планерів, його «політика» і тон.
- [ ] **Логотип.** Сергій надішле ескізи з паперу → оцифрувати й запропонувати варіанти.
- [ ] **Кольорова палітра бренду** → на її основі переробити теми додатку.
- [ ] **Риси, що впізнаються:** візуальні та функціональні фішки, яких немає в конкурентів.

## 4. Дизайн і UI

- [ ] **Вхід і реєстрація:** стильніший дизайн у фірмовому стилі.
- [ ] **Теми:** переосмислити наявні теми під палітру бренду.
- [ ] **Головний екран (Home):**
  - загальний вигляд;
  - дві верхні картки (записи на сьогодні: завершені / в процесі) і картка поточного запису —
    пошукати сучасніші й наочніші способи показати ці дані.
- [ ] **Календар — список записів дня:** коли записів багато й список прокручують, він має розгортатися
  на весь екран, а календар — згортатися зверху в одну стрічку (тиждень).
- [ ] **Календар — шкала зайнятості дня:**
  - ідея лишається: майстер одразу бачить, коли є записи і де перерви, без відкриття дня;
  - записи поза звичними годинами (раніше 8:00 / пізніше 20:00) зараз показуються незрозумілою червоною
    крапкою — придумати зрозуміле відображення;
  - записи, що накладаються, виглядають погано — переробити.
- [ ] **Аналітика:**
  - простіше й зрозуміліше для звичайного користувача, але інформативно;
  - графік виторгу зараз незрозумілий, особливо в режимі «рік» та інших періодах;
  - стовпчики графіка інтерактивні: дотик → сума за цей день / місяць;
  - функції, яких немає в схожих додатках.

## 5. Функції

- [ ] **Нагадування для майстра** про майбутній запис (наприклад, за годину) — як нагадування в Календарі iPhone.
  Технічно: локальні сповіщення iOS, працюють і без інтернету. Налаштування «за скільки нагадувати» — у Settings.
- [ ] **Settings:** додати потрібні параметри (план підписки — див. розділ 2, нагадування — див. вище).
